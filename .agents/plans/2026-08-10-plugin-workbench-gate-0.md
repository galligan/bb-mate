# Plugin Workbench released-capability Gate 0

Date: 2026-08-10
Status: Active
Issue: [#54](https://github.com/galligan/bb-mate/issues/54)
Goal: `.agents/goals/2026-08-10-plugin-workbench/`

## Outcome

Measure six host/plugin capabilities independently using only released
`bb-app@0.36.0` artifacts and disposable state. Use the result to freeze the
next issue graph without importing `../bb`, copying SDK code/types, or touching
the normal bb profile.

## Safety boundary

- Build a clean-room toolchain from the published `bb-app@0.36.0` package or
  verify the workspace binary resolves to that exact npm artifact.
- Use `mktemp -d` for scaffold and runtime state. Set an isolated data directory,
  HOME, XDG config/data/cache, npm/Bun cache, server port, and host-daemon port.
- Prove the selected CLI/server reports 0.36.0 and the isolated data directory
  before any install/reload/disable/remove mutation.
- Native build/types/scaffold commands may run without a server where supported.
- If a lifecycle command cannot be proven isolated, mark only that row
  unavailable and do not run it.
- Do not expose/pair Connect, edit upstream, use normal plugin state, publish,
  sign, tag, or install a private/unpublished SDK.

## Capability matrix

| Row | Capability | Minimum proof |
| --- | --- | --- |
| A | Frontend shell | `bb plugin new --app`; register `navPanel`; refresh types; native build |
| B | Backend supervision | compile `background.service` and `onDispose`; verify package metadata |
| C | Native tools | compile and package bounded agent tool registration |
| D | Skills | compile manifest skill root and conditional agent configuration |
| E | Thread/composer | compile mention provider, thread panel, message action, composer mention/quote |
| F | Lifecycle/live | isolated path install, list/source, reload, disable/enable, remove; no normal state |

Each row records `pass`, `fail`, or `unavailable`, exact commands and versions,
files/dependencies generated by the released CLI, artifact contents, and the
smallest unblock condition. Harness is a separate unavailable fact while
`@bb/plugin-sdk@0.4.1` returns npm E404.

## Execution

1. Audit released CLI flags and identify a fail-closed isolated profile recipe.
2. Create the minimal released scaffold and preserve its dependency/type facts.
3. Add one bounded contract example per row using only generated declarations.
4. Run native types/build and inspect server/app metadata and package contents.
5. Run lifecycle commands only after isolated server/profile proof.
6. Cross-check the matrix with a standing reviewer and a fresh targeted
   reviewer; fix P0–P2 and reasonable P3 findings to 5/5.
7. Append exact evidence and scope amendments to the goal `RETRO.md`, update #54
   and #21, then create/amend the next focused issues.
