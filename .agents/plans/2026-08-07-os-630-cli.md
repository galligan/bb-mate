# OS-630: Native plugin development CLI

## Goal

Ship a private `bb-mate` CLI that discovers and inspects ordinary bb plugin
packages, launches the existing fixture workbench, delegates build and live
development to native bb, and never installs plugins or mutates Connect state.

## Boundaries

- Consume `@bb-mate/inspection`; do not duplicate its compatibility logic.
- Read ordinary manifests only. Never import or execute a plugin entrypoint.
- Resolve the native CLI from `BB_CLI`, then `PATH`, and spawn without a shell.
- Native bb keeps ownership of `plugin build` and `plugin dev`.
- `dev` may read Connect status through inspection, but must not pair, expose,
  install, enable, or otherwise mutate bb.
- Work from the BB Mate repository root or a standalone plugin directory.

## Public behavior

1. `bb-mate [path]` aliases `bb-mate dev [path]`.
2. Selection prefers an explicit path, then a bb manifest in the current
   directory, then exactly one package beneath `plugins/`; ambiguity is an
   actionable error.
3. `inspect [path] [--json]` prints the shared compatibility report and the
   resolved native bb executable/version.
4. `dev [path] [--host <host>] [--port <port>]` launches the existing
   workbench with an absolute `BB_MATE_PLUGIN`, explicit host/port, and strict
   port binding. It reports an existing Connect share only when its port
   matches within the invoking host's authoritative share list, while keeping
   the Connect base URL and global shares distinct.
5. `check [path]` prints inspection, delegates exactly `bb plugin build .` in
   the selected plugin directory with inherited output, preserves failure
   status/signal, and refreshes inspection after a successful build.
6. `live [path]` only delegates `bb plugin dev .` when native inventory points
   at the selected real path. Otherwise it exits with the exact path-install
   command using the resolved native executable and performs no installation.

## Verification

- Follow red-green-refactor vertical slices through the exported CLI runner.
- Use temporary ordinary plugin manifests and fake process/native runners.
- Assert exact argument vectors, cwd, environment, output, exit codes, and
  signal mapping without launching workbench, Connect, or live bb.
- Run the CLI package checks while iterating, then repository format, typecheck,
  tests, and build.
